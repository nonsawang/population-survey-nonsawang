# หลักฐานยืนยันสำรวจรายบุคคล

ติดตั้ง `migrations/20261113_survey_confirmation.sql` ในฐานของเว็บที่ใช้งานจริงก่อนเผยแพร่โค้ดนี้
ต้องมี `population` ที่ใช้ status_model_version 1, `app_users` และ `app_current_user()` จากระบบเดิมแล้ว
Migration รันซ้ำได้ และไม่ยืนยันข้อมูลนำเข้าเดิมอัตโนมัติ

## เกณฑ์
- ยังไม่สำรวจ: ไม่มีหลักฐานการแก้ไข/ยืนยันในระบบใหม่นี้
- ข้อมูลยังไม่ครบ / รอยืนยัน: เคยแก้ไขข้อมูลสำรวจ หรือข้อมูลไม่ตรงกับที่เคยยืนยัน
- สำรวจครบ: เจ้าหน้าที่/อสม.กดยืนยัน ข้อมูลจำเป็นครบ และค่าปัจจุบันตรงกับหลักฐาน
- ข้อมูลจำเป็น: สถานะในบ้าน โรค (รวมการระบุว่าไม่มีโรค) Type และสถานะจำหน่าย
- หน้าบ้านของฉันนับเฉพาะ Type 0–3/ยังไม่ระบุ ที่ยังไม่จำหน่ายและใช้โมเดลสถานะใหม่
- พิกัด คัดกรอง และการส่ง HOSxP แยกจากสถานะสำรวจ

## การตรวจสิทธิ์และข้อมูล
RPC ใช้บัญชีจาก session ฝั่งฐานข้อมูล ไม่รับผู้ยืนยันหรือเวลาจากเบราว์เซอร์
อสม.อ่าน/ยืนยันเฉพาะหมู่ที่ได้รับสิทธิ์และชื่อเจ้าของงานตรงกับบัญชี เจ้าหน้าที่/admin เข้าถึงได้ตามบทบาท
การยืนยันล็อกแถวและเทียบข้อมูลที่แสดงบนการ์ดกับฐานก่อนสร้างหลักฐาน
ตารางหลักฐานไม่เปิดให้ anon/authenticated อ่านหรือเขียนโดยตรง
แก้ข้อมูลสำรวจแล้วต้องยืนยันใหม่ การเขียนค่าซ้ำและการเปลี่ยนข้อมูลคัดกรอง/GPS ไม่สร้างหลักฐานสำรวจใหม่

## ทดสอบ
`node tests/survey-confirmation.cjs` ใช้ PostgreSQL ผ่าน PGlite แยกจากฐานจริง
ทดสอบ migration ซ้ำ, scope, ข้อมูลไม่ครบ, stale snapshot, ยืนยันซ้ำ, ประวัติหลังแก้ไข และการรวมยอดบ้าน
ก่อนเปิดจริงให้ทดสอบด้วยบัญชี อสม. เลือกชื่อจาก `/my-houses` ตรวจการเปิดการ์ดและยืนยันหนึ่งรายการที่ได้ตรวจจริง
ยังต้องตรวจบนมือถือ/LINE จริง ไม่ควรกดยืนยันข้อมูลประชาชนเพื่อทดสอบโดยไม่ได้สำรวจ

หน้าบ้านของฉันเก็บรายงานเดิมไว้ในหัวข้อพับเก็บสำหรับพิมพ์ใบงาน โดยระบุว่าเกณฑ์เดิมเป็น Type ไม่ใช่หลักฐานยืนยัน
