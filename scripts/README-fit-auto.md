# Automatic FIT LAN import

Current host setup: Task Scheduler registration failed with "The system cannot find the path specified"; Windows also disallows unsigned PowerShell scripts. No execution policy was changed. Instead `node scripts/fit-auto-launcher.cjs --watch` runs the same bounded cycle every 60 seconds in a hidden background process. `lan-runtime/auto.pid` records the launched process. This mode does NOT restart after reboot/logoff or a process crash. Set enabled=false in auto.json to stop after the current cycle. The launcher logs results and keeps existing retry state. A system administrator can later register the Node executable and launcher directly (no PowerShell execution policy change required).

The Windows task `Nonsawang-FIT-AutoImport` checks every minute while the configured Windows user is logged in and the computer is awake/on the hospital LAN. Each cycle attempts one approved, prepared FIT job. It does not automatically approve screening results or submit claims. Its existing writer creates visit, lab and PP Special and reports VN to the web. The in-facility PP mapping applies.

Install using `scripts/install-fit-auto.ps1 -Scope include_existing -NodePath <absolute node_modules directory>` for the explicitly authorized backlog, or `-Scope new_only` to freeze a UTC cutoff at installation. Requires mysql2 and @supabase/supabase-js in that directory and the existing `.env.sync`. No credentials are included in the task command. Windows may require an administrator to register a task.

`lan-runtime/auto.json` controls activation (`enabled`), scope, cutoff and batch limit. Set enabled=false or disable the task to pause future cycles. An import already in progress is allowed to finish its transaction. The runtime directory is gitignored; do not upload it. The worker uses a database cycle lock plus per-preparation writer locking and the transaction ledger. Completed jobs are skipped; committed jobs whose web acknowledgement failed recover the original VN.

The snapshot refreshes after one hour. Patient identity, approval and current results are checked again by the writer. Failed jobs wait 5, 10, 20, 40, then 60 minutes, with at most five attempts. After five attempts, inspect the source and `auto.json.state.json` before removing that job's retry record to allow another attempt. Never delete HOSxP ledger rows. Logs contain counts/error codes, not patient names or CID. `auto.log` rotates at 1 MB.

Validation: `node tests/hosxp-fit-auto.cjs` exercises cutoff configuration, bounded processing, skip completed, durable cooldown, retry cap and acknowledgement recovery. `node tests/hosxp-fit-writer.cjs` covers atomic writer behavior including PP failure rollback. Production use must also verify Task Scheduler's LastTaskResult and the runtime log; successfully registering a task alone does not prove an import ran.
