# ตัวเชื่อมตรวจคิว FIT ใน LAN

รันบนเครื่องใน LAN ที่มี Node.js และ dependencies ของโครงการ ใช้ `.env.sync` เดิม เก็บ service-role key เฉพาะเครื่องนี้ ห้ามใส่ในเว็บหรือ commit ไฟล์ secrets

```powershell
node scripts/validate-hosxp-fit-queue.cjs
```

ตัวเชื่อมนี้ทำงานครั้งเดียว ตรวจ mapping ของ HOSxP แล้วอ่านรายการ `awaiting_lan_validation` ที่เจ้าหน้าที่เตรียมบนเว็บ ตรวจว่ามีประวัติและการอนุมัติ ผลยังตรงกับข้อมูลล่าสุด ยืนยันเลขบัตรและจับคู่ person/patient ได้คนเดียว ตรวจ person_id และ patient_hn รวมถึงแล็บ FIT/ค่าบริการเดิมในวันเดียวกัน

ผลเป็น JSON มีเฉพาะรหัสรายการเตรียม สถานะ และยอดรวม ไม่พิมพ์เลขบัตร HN ชื่อผู้ป่วย หรือ credentials

| สถานะ | ความหมาย |
|---|---|
| VALIDATED_NOT_IMPORTED | ตรวจผ่าน ณ เวลานั้น ยังไม่สร้าง visit |
| SOURCE_CHANGED | ผลมีการเปลี่ยนแปลง ต้องตรวจข้อมูลล่าสุด |
| DUPLICATE_PERSON_CID / DUPLICATE_PATIENT_CID | เลขบัตรจับคู่ได้หลายรายการ ต้องแก้ที่ปลายทาง |
| TARGET_CHANGED_SINCE_SYNC / HN_LINK_CONFLICT | รหัส HOSxP เปลี่ยนจากชุดซิงก์ หรือ HN เชื่อมไม่ตรง |
| EXISTING_FIT_REQUIRES_REVIEW / EXISTING_FIT_FEE_REQUIRES_REVIEW | มีแล็บหรือค่าบริการวันเดียวกัน ต้องตรวจรายการเดิม |
| DECEASED_REQUIRES_REVIEW | ปลายทางระบุเสียชีวิต ต้องตรวจสอบ |

ไม่มีคำสั่งเขียน HOSxP หรือ Supabase และยังไม่รายงานสถานะกลับหน้าเว็บ การตรวจผ่านไม่ใช่อนุญาตนำเข้า ต้องตรวจซ้ำ ณ เวลาที่เขียนจริง ตัวตรวจนี้ไม่ยืนยันสิทธิรักษา เวลา visit หรือความครบถ้วนของ workflow HOSxP

ทดสอบ: `node tests/hosxp-fit-lan.cjs`

ผลตรวจเดิมที่รายงานคิวว่างเกิดจากใช้ anon key ผิดชนิด จึงถูก RLS กรองออก แก้ตัวเชื่อมให้ปฏิเสธคีย์ผิดชนิดแล้ว ผู้ใช้แก้คีย์และอนุญาตใช้ฐานจริงแล้ว ไม่ต้องขอฐานทดสอบซ้ำ

## ทำงานแบบซิงก์ร่วมกับตรวจสด

รัน `node scripts/run-hosxp-hybrid.cjs` บนเครื่อง LAN: ซิงก์ snapshot ให้ครบและตรวจจำนวนก่อนเปิดใช้ จากนั้นตรวจคิว FIT กับ HOSxP สด ใช้เฉพาะการเชื่อมต่อขาออก HTTPS ไป Supabase ไม่เปิด listener หรือพอร์ตฐานข้อมูลเข้าจากอินเทอร์เน็ต

เว็บค้นหาข้อมูลใน Supabase ตามเดิม ตัวเชื่อมใช้ snapshot ล่าสุดไม่เกิน 24 ชั่วโมงจับคู่ CID ต้องไม่ซ้ำทั้งสองฝั่ง และเปรียบเทียบรหัส HOSxP ที่ซิงก์ไว้กับรหัสสด รหัส population.person_id ของเว็บเป็นอีก namespace และไม่ถูกแก้ทับ ตรวจชื่อ นามสกุล วันเกิด กับทั้ง person และ patient รวมถึง HN และรายการแล็บ/ค่าบริการซ้ำในวันคัดกรอง

รันจริง 16 ก.ย. 2569 เวลา 10:05 น.: ซิงก์ snapshot 19,035 รายการ คิว FIT 22 รายการผ่าน VALIDATED_NOT_IMPORTED ไม่มีการเขียน HOSxP หรือสร้าง VN ผลนี้เป็นการตรวจ ณ เวลานั้นเท่านั้น

คำสั่งทำงานครั้งเดียว ยังไม่ได้ติดตั้งงานรันอัตโนมัติ และผลตรวจรายคิวยังไม่ได้ส่งกลับหน้าเว็บ ยังไม่มีตัวสร้าง visit ต้องตรวจข้อมูลซ้ำใน transaction ก่อนเขียนจริง และพัฒนาการออกเลข VN/รายการบริการ การป้องกัน retry ซ้ำ และ acknowledgement ให้ครบก่อนเปิดนำเข้า
